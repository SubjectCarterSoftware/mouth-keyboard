  <action>
    Create `Speech2Text/Conversion/LLMRewriteService.swift` and add it to the Speech2Text target.

    Implementation requirements:
    - Mirror the existing `WhisperService` pattern in one file: define `LLMRewriteError`, `LLMRewriting`, and `LLMRewriteService`.
    - Keep `LLMRewriteService` as a plain actor. Do not annotate it or its protocol with `@MainActor`.
    - Expose `func rewrite(body: String, mode: ConvertMode) async throws -> String` behind `LLMRewriting`.
    - Include `static let shared = LLMRewriteService()` for the production singleton.
    - Import the real libraries the research calls for: `Foundation`, `Hub`, `MLXLLM`, and `MLXLMCommon`.
    - Resolve a persistent download base under Application Support, for example `~/Library/Application Support/Speech2Text/RewriteModel`, and create `HubApi(downloadBase:)` from that location instead of using the default purgeable caches path.
    - Lazy-load `LLMRegistry.qwen2_5_1_5b` through `LLMModelFactory.shared.loadContainer(...)`.
    - Cache the loaded `ModelContainer` and deduplicate first-use work with `loadTask: Task<ModelContainer, Error>?` so concurrent first rewrites await the same load instead of starting duplicate downloads.
    - Add an explicit serialization gate for rewrite execution. Do not rely on actor isolation alone, because the actor can re-enter across awaits. A second `rewrite(body:mode:)` call must wait until the first call's generation path is complete before starting its own MLX session work.
    - Create a fresh `ChatSession` for every `rewrite(body:mode:)` call. Use `mode.defaultSystemPrompt` as `instructions:` and keep generation parameters bounded and deterministic (`temperature: 0`, `topP: 1.0`, and a `maxTokens` value large enough to avoid routine truncation while still treating truncation as failure).
    - Use `streamDetails(to:images:videos:)` instead of `respond(...)`. Accumulate `.chunk` text into a local buffer and inspect the final completion info.
    - Map failure semantics exactly to the Phase 8 contract:
      - model-load failure -> `.modelLoadFailed`
      - thrown generation/stream failure -> `.generationFailed`
      - task cancellation or `.cancelled` stop reason -> `.cancelled`
      - `.length` stop reason -> `.outputTruncated`
      - empty or whitespace-only final output -> `.emptyOutput`
    - Never return partial output on any failure path. If a chunk buffer exists and the call fails later, discard it and throw.
    - Keep a deterministic test seam in the same file so unit tests can substitute a fake loader and fake per-call session factory without downloading the model. An internal initializer or fileprivate backend protocol is fine; do not create extra production source files for this.
    - Do not touch `ActivationStore`, clipboard fallback logic, the 350-word guard, or any shell/UI files in this plan.
