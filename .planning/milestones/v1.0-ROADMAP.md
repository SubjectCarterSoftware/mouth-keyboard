# Milestone v1.0: Speech2Test

**Status:** SHIPPED 2026-03-08
**Phases:** 1-5
**Total Plans:** 13

## Overview

Speech2Test v1.0 ships a macOS menu bar dictation utility that stays in the background, starts from a global hotkey, records immediately, transcribes locally, and copies final text to the clipboard. The shipped milestone includes setup/readiness handling, activation and capture, local transcription, recovery controls, and long-dictation reliability.

## Phases

### Phase 1: Foundation and Permissions

**Goal**: Ship a native menu bar utility that can stay in the background, persist basic settings, and clearly onboard the required macOS permissions.
**Depends on**: Nothing (first phase)
**Plans**: 2 plans

Plans:

- [x] 01-01: Build the native app shell, menu bar presence, and persistent settings foundation.
- [x] 01-02: Implement permission detection, onboarding flow, and readiness state handling.

**Details:**
- Established a menu-bar-first shell, transient setup window, and readiness-backed status surfaces.
- Added capability-based microphone and keyboard-monitoring permission handling with recovery links and UI smoke coverage.

### Phase 2: Activation and Capture

**Goal**: Let the user configure activation behavior and start recording immediately from any app with the chosen microphone and uninterrupted system audio.
**Depends on**: Phase 1
**Plans**: 3 plans

## Milestone Summary

**Key Decisions:**
- Clipboard-only output remained the v1 compatibility boundary.
- The shipped interaction model is single-tap hotkey start/finish, not double-tap or spacebar finish.
- Long sessions transcribe sealed segments progressively, but clipboard writes remain gated behind final assembly.
- `ActivationStore` can re-arm immediately from terminal success/failure feedback while still blocking during active processing.
- The bundled transcription model was switched to `ggml-tiny.en.bin` at closeout to reduce perceived latency on the target machine.

**Issues Resolved:**
- AVAudioEngine startup/order issues that caused capture instability.
- Recovery-path clipboard corruption risk during cancel/restart/microphone failure.
- Long-session hotkey re-entry freeze after terminal success feedback.

**Issues Deferred:**
- Phase verification and requirement traceability gaps called out in `.planning/v1.0-MILESTONE-AUDIT.md`.
- Silence-warning feedback still exists only in logs, not the pill UI.
- Clipboard success-path write failure is not surfaced to the user yet.

**Technical Debt Incurred:**
- Phase 2 and Phase 5 lack dedicated `VERIFICATION.md` closeout artifacts.
- Some planning documents still reference removed double-tap or spacebar behavior.
