## Overview

Replaced full-transcript fuzzy command scanning with a named AI trigger boundary (`Zeus` default) so instructions are interpreted only after the trigger name. Shipped named trigger identity with persistence, three-sample voice calibration, last-name-wins transcript splitting, conservative predefined intent routing, custom LLM fallback for unmatched instructions, and a settings UI for trigger name configuration.

## Milestone Summary

**Key Decisions:**
- Named trigger boundary replaces whole-transcript fuzzy command scanning
- Last-occurrence trigger split (`last-name-wins`) avoids false activation from earlier mentions
- Whole-word boundary matching (`\b...\b`) prevents substring aliases from activating parser
- `TriggerProfileStore` is a dedicated file-backed actor isolated from convert-mode UserDefaults keys
- Save-before-publish semantics throughout: runtime state only updates after successful store writes
- `detectPredefinedShortcut` is a separate detection path from general intent detection
- `ConvertIntent.effectiveSystemPrompt` carries post-trigger instruction to custom LLM fallback
- `CalibrationCapturingDone` error type as exit sentinel for clean capturer exhaustion
- UI tests use `/tmp/Speech2Test.UITests/` store (deleted on each launch) for trigger-profile isolation

**Issues Resolved:**
- Substring alias activation (`atlas` matching in `atlases`) — fixed with `\b` whole-word matching
- `StubCalibrationSampleCapturer` infinite loop on exhaustion — fixed with `CalibrationCapturingDone.exhausted` sentinel
- `IntentDetector` trailing-position false classification — fixed by using lower bounds instead of upper bounds
- Built-in fuzzy false positives on custom command phrases — fixed with keyword-signal gate on non-exact matches

**Tech Debt Carried Forward:**
- `AIAssistantTileView.body` creates `AIAssistantSettingsViewModel` on every render — should be `@StateObject`
- `AssistantCalibrationRunner.countAccepted()` always returns `0`; `onSampleAccepted` callback `Int` parameter is unused
- `AIAssistantSettingsFlowTests` (14 UI tests) fail at XCUITest runtime — pre-existing issue, non-blocking
- Phases 12-15 have no `VALIDATION.md` files (Nyquist compliance not assessed)
