### Non-blocking Integration Concerns

1. **SETT-01 — `AIAssistantTileView` vm construction in `body`:** `AIAssistantSettingsViewModel` is instantiated on every SwiftUI render pass inside `body`. The Combine subscription to `preferences.$activeTriggerProfile` is immediately orphaned after the render. The tile updates correctly in practice because `@ObservedObject preferences` drives redraws when the profile changes — but the subscription lifecycle is inverted from SwiftUI best practice. Low risk; works in all tested paths. Recommend extracting vm to `@StateObject`.

2. **CAL-01 / SETT-03 — `onSampleAccepted` always passes `0`:** `AssistantCalibrationRunner.countAccepted()` always returns 0; the callback always delivers `0` as the accepted-count argument. The UI consumer (`AIAssistantSettingsView`) ignores the argument and self-increments an `@State calibrationAccepted` counter, so the UI is correct. The callback parameter carries no information. Recommend removing the `Int` parameter or fixing `countAccepted()`.
