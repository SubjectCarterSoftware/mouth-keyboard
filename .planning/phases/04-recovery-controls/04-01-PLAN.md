<objective>
Implement the Phase 4 recovery foundation for cancel and restart, including explicit session invalidation, literal `Escape` cancel wiring, and visible confirmation in the current shell surfaces.

Purpose: Phase 3 can finish and transcribe, but it cannot yet recover safely from an accidental recording or an in-flight cancel. This plan establishes the recovery state model and the background keyboard path needed for trustworthy cancel/restart behavior.
Output: Explicit cancel/restart APIs in `ActivationStore`, session-key interception for `Escape`, menu-based recovery affordances, and transient canceled/restarted confirmation in the pill/menu.
</objective>

  <action>
    Extend `ActivationStore` so recovery is explicit and testable instead of being inferred from `.idle`.

    Implementation requirements:
    - Add a companion `RecoveryFeedback` signal (for example `.canceled` / `.restarted`) instead of overloading `RecordingState`; restart must keep `state == .recording`.
    - Track `activeSessionID`, the current transcription `Task`, and any delayed dismiss / feedback-clear tasks so cancel or restart can invalidate every in-flight branch.
    - Introduce `cancelCurrentSession()` and `restartCurrentSession()` APIs. Keep `stop()` only as a thin compatibility wrapper if a temporary bridge is needed, but migrate production call sites to the explicit recovery APIs inside this plan.
    - `cancelCurrentSession()` must work from both `.recording` and `.processing`: cancel the transcription task, invalidate the session token, reset the buffer accumulator, clear pending dismiss timers, publish `.canceled`, and land in `.idle`.
    - `restartCurrentSession()` must only be valid while `.recording`: invalidate the session token, reset the buffer accumulator, invoke an injected reset hook for level/silence state, keep `state` in `.recording`, and publish `.restarted` on a short auto-clear timer.
    - Update `finish()` so it assigns a fresh session token, stores the task handle, and guards every async completion branch with `Task.isCancelled` plus token equality before mutating state or touching the clipboard.
    - Treat empty or whitespace-only transcription as no usable result. That path must stay in the failure/recovery lane and must not call `ClipboardService`.

    Test coverage to add in `ActivationStoreTests.swift`:
    - cancel during recording tears down to idle and never writes the clipboard
    - cancel during processing suppresses late success or failure publication
    - restart keeps `.recording`, resets the buffer, and clears feedback on schedule
    - cancel and restart both leave the clipboard untouched
    - empty / trimmed transcription does not reach the clipboard
  </action>

  <done>
    - `ActivationStore` exposes explicit cancel/restart APIs with session invalidation
    - stale async completions cannot overwrite state or clipboard after cancel/restart
    - restart does not bounce through `.idle` or restart the audio engine
    - `ActivationStoreTests` cover cancel/restart/clipboard safety regressions
  </done>
