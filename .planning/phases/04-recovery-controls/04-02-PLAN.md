<objective>
Harden microphone/input-failure handling and finish the clipboard-safety contract for no-output recovery paths.

Purpose: Phase 4 is only trustworthy if microphone failures are visible and if the clipboard remains intact whenever the session is canceled, fails, or yields no usable text. This plan turns the current logged-or-silent failures into typed user-facing recovery behavior.
Output: Typed microphone failures from `AudioCaptureService`, store/app wiring that preserves clipboard integrity on every no-output path, and menu/pill recovery messaging for denied, unavailable, or disconnected input.
</objective>

@MainActor

Current audio and failure seams that must be upgraded:

```swift
enum AudioCaptureError: LocalizedError {
    case noInputDevice
    case engineException(NSError)
}
```

```swift
private func onRecordingStarted() {
    do {
        try audioCaptureService.start(...)
    } catch {
        NSLog("AudioCaptureService failed to start: \(error.localizedDescription)")
        activationStore.stop()
    }
}
```

```swift
@MainActor
private func handleSelectedDeviceDisconnect() {
    preferences.micDeviceUID = nil
    stop()
    try start(levelMonitor: currentMonitor, bufferAccumulator: currentAccumulator)
}
```

The executor must remove the silent-fallback behavior and preserve the clipboard by avoiding writes on every no-output path.

  <files>

  <action>
    Extend the 04-01 recovery foundation so every input failure and no-output path preserves the clipboard.

    Implementation requirements:
    - Add `handleCaptureFailure(_:)` to `ActivationStore`. It must invalidate the current session token, cancel any in-flight transcription task, reset the buffer accumulator, clear transient recovery timers, and transition into the correct typed failure state.
    - In `AppDelegate`, route both start-time `AudioCaptureService.start(...)` failures and mid-session disconnect callbacks into `handleCaptureFailure(_:)`. Do not log and drop back to `.idle`.
    - Keep the clipboard as a strict write barrier: only a current-session, non-empty success path may call `ClipboardService`. Cancel, restart, no speech, empty/trimmed transcript, microphone denial, microphone unavailability, disconnect, and stale async completions must all avoid the pasteboard entirely.
    - Do not try to "restore" the clipboard after a failed write. The correct behavior is to prevent the write from starting on every no-output path.
    - Extend `ActivationStoreTests.swift` so mic failures, empty transcripts, and stale completions after a capture failure all assert that the clipboard was never touched.
  </action>
  <verify>xcodebuild test -project Speech2Test.xcodeproj -scheme Speech2Test -only-testing Speech2TestTests/ActivationStoreTests -destination 'platform=macOS'</verify>
  <done>
    - capture failures move through `ActivationStore` as typed user-visible failures
    - no-output paths cannot begin a pasteboard write
    - clipboard integrity is enforced for cancel, failure, and empty-result cases
    - `ActivationStoreTests` cover capture-failure and empty-result clipboard safety
  </done>
