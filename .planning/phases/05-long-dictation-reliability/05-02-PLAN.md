Implement ordered transcript assembly, best-effort partial-failure handling, and the persistent long-session status surface.

Purpose: After Plan 01 seals segments reliably, Phase 5 still needs to turn those segment results into one final clipboard outcome that preserves spoken order and warns clearly when the combined result is incomplete.

Output: finalization logic in `ActivationStore`, a dedicated transcript assembler, one final clipboard barrier for the session, and menu-bar status/warning plumbing for long-session completion.

  <action>
    Turn Plan 01's queued segments into one final session result that respects order and best-effort behavior.

    Implementation requirements:
    - Create `LongDictationAssembler.swift` with a dedicated assembler contract that:
      - sorts segment results by stable `index`
      - trims segment text
      - treats empty / whitespace-only segment output as failure, not success
      - joins successful segment text into seamless prose
      - reports `failedSegmentCount` and `successfulSegmentCount`
    - Extend `ActivationStore` so sealed segments begin transcription work through the existing `WhisperService` actor without assuming completion order matches spoken order.
    - Refactor `finish()` into a true finalization step for long sessions:
      - close any remaining live segment
      - transition to `.processing`
      - wait for queued segment work to settle
      - assemble best-available results
      - if at least one segment succeeded, write exactly one final clipboard result
      - if all segments failed, land on the failure path and leave the clipboard unchanged
    - Preserve Phase 4's clipboard barrier: cancel, restart, stale completions, and all-failure paths must not begin a clipboard write.
    - Store partial-failure metadata in companion state instead of polluting the clipboard text.

    Test coverage to add:
    - `TranscriptAssemblerTests.swift`
      - out-of-order completion still assembles in spoken order
      - whitespace normalization produces seamless combined prose
      - partial failures increment the warning count without blocking successful output
      - all-failure input yields no assembled transcript
    - `ActivationStoreTests.swift`
      - a multi-segment session writes to the clipboard once at finalization
      - partial failure still succeeds with a warning count
      - all-failure long sessions do not write the clipboard
      - stale segment completions after cancel are ignored
  </action>

  <done>
    - ordered assembly is independent of transcription completion order
    - partial failure produces best-effort combined output when any segment succeeds
    - the clipboard is written exactly once per successful long session
    - all-failure and stale-result paths remain clipboard-safe
  </done>
</task>
