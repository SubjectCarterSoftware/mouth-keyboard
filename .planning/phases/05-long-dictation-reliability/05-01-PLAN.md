Output: `ActivationStore` long-session session tracking, immutable segment payloads from `AudioBufferAccumulator`, pause/soft-cap boundary signaling, and focused unit coverage for segmentation behavior.

    Implementation requirements:
    - Add fixed long-dictation threshold tracking in `ActivationStore`. Before the threshold, keep the current single-buffer behavior unchanged.
    - After the threshold activates, a natural pause should usually close the current segment. If there is no usable pause, a soft cap must still close the segment so the session cannot grow indefinitely.
    - Implement or extract deterministic boundary logic that can be unit tested directly. Avoid burying the decision in wall-clock-only UI callbacks.
    - Keep `ActivationStore.state == .recording` while segments are being sealed during active dictation. Segmenting earlier audio must not stop the engine or enter `.processing`.
    - Queue sealed segments in order with stable indices and `pending` transcription state, but do not implement final assembly in this plan.
    - Update `AppDelegate` to route any new pause/soft-cap callbacks from `AudioLevelMonitor` into `ActivationStore` while preserving the existing capture start/stop lifecycle.
    - Preserve existing Phase 4 recovery guarantees: cancel and restart must still invalidate current-session work and clear long-session state safely.

    Test coverage to add:
    - `ActivationStoreTests.swift`
      - sessions under the threshold do not seal segments
      - long sessions seal a segment on a pause after threshold activation
      - soft-cap sealing works when no pause occurs
      - segment sealing keeps the store in `.recording`
    - `LongDictationBoundaryTests.swift`
      - deterministic threshold -> pause -> seal decision
      - deterministic threshold -> overrun -> soft-cap decision
      - no boundary emitted before the long-session threshold
