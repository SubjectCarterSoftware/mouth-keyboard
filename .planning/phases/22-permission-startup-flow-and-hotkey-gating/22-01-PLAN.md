**D-01:** Call `CGRequestPostEventAccess()` (via PostEventPermissionService) in `applicationDidFinishLaunching`, after the existing `hotkeyService.start()`.
**D-02/D-11:** Add a 0.75s delay between the Input Monitoring side-effect prompt and the Accessibility prompt.
**D-03/D-12:** Always prompt for Accessibility regardless of Input Monitoring result.
**D-04:** Fire-and-forget. Use the existing `hasRequestedPostEventPermission` flag — only auto-prompt once per install.
**D-05:** Call `readinessStore.refresh()` after the prompt completes.
**D-10:** Prompt order: Input Monitoring first (existing side-effect from `hotkeyService.start()`), then Accessibility.

**Step 1:** Add a `postEventService` property to AppDelegate at line ~12, after the existing property declarations:
```swift
private let postEventService = PostEventPermissionService.live
```

**Step 2:** Insert the following code in `applicationDidFinishLaunching`, immediately after `readinessStore.refresh()` (line 28) and before the `do { try WhisperService.deleteLegacyUnsupportedModelFiles() }` block (line 30):

```swift
// Auto-prompt Accessibility permission after a short delay so the
// Input Monitoring dialog (triggered by hotkeyService.start() above)
// does not stack with the Accessibility dialog.
if !preferences.hasRequestedPostEventPermission {
    preferences.recordPostEventPermissionPrompt()
    DispatchQueue.main.asyncAfter(deadline: .now() + 0.75) { [weak self] in
        guard let self else { return }
        self.postEventService.requestAccess()
        self.readinessStore.refresh()
    }
}
```

**Key details:**
- `preferences.recordPostEventPermissionPrompt()` is called BEFORE the delayed block so the flag is set even if the app crashes during the prompt (per Pitfall 2 from research).
- `[weak self]` prevents retain cycle through the dispatch closure.
- `readinessStore.refresh()` inside the delayed block updates the setup window after the prompt resolves (per D-05).
- The existing `readinessStore.refresh()` on line 28 remains — it updates immediately for Input Monitoring status. The delayed refresh updates for Accessibility status.
- Uses `DispatchQueue.main.asyncAfter` (not `Task.sleep`) for consistency with the existing `asyncAfter` pattern on line 55 of the same file.
